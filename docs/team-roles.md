# Rollen und Verantwortlichkeiten

| Entscheidung / Arbeit | Product Owner | Tech Lead | Developer | Reviewer / QA |
|---|---|---|---|---|
| Vision, MVP, Priorisierung | **entscheidet** | berät | berät | informiert |
| Feature-Definition und G1 | **genehmigt fachlich** | prüft technische Risiken | schätzt/klärt | unterstützt |
| Architektur / ADR | wird konsultiert | **entscheidet** | berät | prüft Risiken |
| Feature-Implementierung | informiert | koordiniert Schnittstellen | **verantwortet** | informiert |
| PR / technische Abnahme | informiert | prüft kritische Änderungen | liefert Nachweise | **reviewt** |
| G2 Testbereitschaft | informiert | verantwortet Integration | liefert Build | prüft Voraussetzungen |
| G3 Releasefreigabe | **fachlich** | **technisch/betrieblich** | unterstützt | stellt Testnachweise bereit |
| G4 Nächste Iteration | **entscheidet** | berät | berät | bringt Findings ein |

## Grundregeln
1. Entscheidungen gehören zu **Menschen**, KI-Agenten sind Werkzeuge.
2. Eine Person kann mehrere Rollen tragen; Zuständigkeiten bleiben explizit.
3. Bei Teams: mindestens eine **andere** Person prüft den PR; kritische Änderungen erfordern zusätzlich den zuständigen Codeowner, soweit dies in der Repository-Konfiguration technisch erzwungen werden kann.
4. GitHub Issue = operativer Owner/Status; Feature-Plan = fachlicher Vertrags- und Review-Nachweis; ADR = langlebige Architekturentscheidung.
5. Bei Abwesenheit ist eine benannte Vertretung erforderlich; stillschweigende Freigabe gibt es nicht.
